# unfold：把材料读成一场课

这个技能的产出不是摘要，是**一堂能上完的课**。四步，顺序不能换。

## 0. 先看清楚手里的牌（不要跳过）

- 用户说的是文件路径就用 `unfold_ingest` 导入；只给了标题/链接，先问清楚文件在哪。
- 导入后**不要**立刻通读全文。先 `unfold_read` 读目录页、摘要、引言和结论（通常 5–8 页），
  对「这篇材料想解决什么」有判断，再决定哪里值得细读。
- 语言的默认选择：原文是英文就用中文讲，专业名词第一次出现时保留英文原词。

## 1. 摸底（先问，再讲）

读完开头后，**问 3 个问题**，每个问题给出可选项，让用户一两句话就能回答：

1. **你现在的起点**：这些概念里哪些是你熟的？（从材料里挑 3–4 个真出现的术语，不要泛泛问"你了解多少"）
2. **这次想到哪**：是想跟上作者的论证、能自己复现/推导、还是只要能跟人讨论？
3. **有多少时间**：30 分钟、2 小时、还是整个下午？

规则：
- 问题必须**基于材料**（引用具体术语、具体章节），问出「你到底卡在哪」。
- 用户说「随便」「你看着办」→ 按默认档继续：起点=知道基本定义，目标=能讲清主线，时间=1 小时。
  **不要反复追问**，一次问清，答不上来就按默认走。
- 用户已经说清了自己的起点和目标 → 直接进第 2 步，别走形式。

## 2. 排最短路线（并说出你砍掉了什么）

写一段路线，包含：

- 从起点到目标要经过的 **3–6 个节点**，每个节点一句话说明「为什么必须经过它」。
- **明确列出跳过的部分**：「第 4 节的实现细节、附录 B 的实验设置这次跳过，不影响主线」。
  这句话比路线本身更重要——它让用户相信你读过、也知道什么不重要。
- 缺的前置知识：如果某块卡点需要材料里没有的背景（比如线性代数里某个概念），
  **补一小节**（`kind: "def"`），并在讲课里说清「这是补的，不是你原文里的」。

用户认可路线（或说「开始吧」）再写讲义。

## 3. 写到够用为止（若无必要，不增实体）

写 `notes.json`（结构见 `references/notes-schema.md`，照抄字段名），然后 `unfold_build`。

硬规则：

- **一节一个点**。一节的标题就是这一节的结论，不是话题名。
  ✅「注意力之所以能并行，是因为它不依赖上一步的输出」 ❌「注意力机制介绍」
- **一段不超过三句**。写第四句之前先问：删掉它，读者还能懂吗？
- **术语第一次出现必须定义**，用 `kind: "def"`，一句话说完。不要在定义里套定义。
- **每处引用都必须是原文原句**。先用 `unfold_search` 找到那句话，再把它原样粘进 `quote`。
  定位不到就换句子，或者不引用——**宁可少一个引用，也不要编造页码或转述的"引文"**。
- **不写文献综述腔**：「近年来……受到了广泛关注」「本文提出了一种……」这类句子一律删掉。
  讲义里只有「是什么、为什么、怎么看出来的」。
- **公式只写用得上的**。写不出推导过程就只给结论和它的含义，不要抄一堆符号装作严谨。
- 用户的起点决定了省略程度：答「我熟」的概念，一句话带过甚至直接跳过。

写完以后自己检查一遍：把任何一句「删掉读者也不受影响」的话删掉，再 build。

## 4. 给你讲课

讲义的 `lecture` 是一串节拍（beat），每个节拍对应一段内容，顺序就是讲课顺序：

- `say` 是**口语**，1–2 句，不超过 60 字，像人在讲台上说的话，不是书面语复述。
  ✅「这里作者换了个视角：既然每个词都要看其他所有词，那就不需要一步一步来了。」
  ❌「本节阐述了注意力机制不依赖序列顺序的特性。」
- 每个节拍**只讲一件事**，讲不完就多拆一个节拍。
- 节拍覆盖全文，不要停在半路；通常在 8–20 个之间。太少了等于念稿，太多了等于没重点。
- 重要结论的节拍写 `"point": true`，讲到这里时会亮起激光笔。
- 可选 `anim`：给大肥鱼挑一个姿态，从这几个里选（必须原样写）：
  「写代码」（板书推导，默认）、「轻快记录」、「深度思考碎碎念」、「原地敲击桌面互动」。
  不确定就不写，用默认。

## 工具顺序（照做即可）

```
unfold_ingest   { files: ["a.pdf", "b.pdf"], title: "..." }      → 项目 slug、文档 id（p1、p2…）
unfold_read     { project, doc: "p1", from: "1", to: "8" }        → 读页
unfold_search   { project, query: "exact phrase" }                → 拿到 p.N + 原句
写 notes.json（用文件写入工具，别用工具参数硬塞大 JSON）
unfold_build    { project, notesFile: ".unfold/<slug>/notes.draft.json" }
unfold_status   { }                                               → 查项目/截图/大肥鱼状态
```

build 成功后告诉用户三件事：文件路径（可双击离线打开）、怎么用
（空格播放讲课、← → 翻节拍、引用悬停/点击看原页截图、1–4 折叠层级）、
以及「🐟 按钮能开关大肥鱼联动」。

讲课默认用云端「云健」音色朗读（讲义底部的下拉框可以换成别的音色或浏览器自带声音），
所以 `say` 要写得**念出来好听**：短句、少用括号和符号、数字用中文读法（「十二层」而不是「12层」）。

## 失败与边界

- `unfold_build` 报「N 处 quote 没能在该页找到」→ 用 `unfold_search` 找准确原句，
  改 `quote` 后重跑。不要靠猜页码。
- 只写了页码、没写 `quote` 的引用是合法的「指路」引用：不截图，只显示页码。
- 项目里没有截图渲染能力 → 引用只显示原文文字，照常交付，并在回复里说明。
- 项目里没有截图渲染能力 → 引用只显示原文文字，照常交付，并在回复里说明。
- 材料是扫描件（无文本层）→ `unfold_read` 会读出空文本。这时改用视觉读 PDF 的能力逐页看，
  并在讲义里只用你**确实看见**的内容，不要补脑原文。
- 用户只想快速问一篇论文的结论 → 不需要走完这套，直接读并回答；unfold 是给「要真读懂」的场景用的。
